# Как править bear-skills

Это личная коллекция, но устроена так, чтобы её можно было форкнуть и вести дальше. Ниже — правила, которые держат репозиторий в порядке.

## Один источник правды

Редактируется **только `domains/`**. Каталоги `skills/`, `agents/`, `rules/` в корне — сгенерированное зеркало для плагина Claude Code и `npx skills add`. У каждого файла зеркала в шапке стоит предупреждение, а CI проверяет, что оно не разошлось с источником.

```bash
make mirror        # пересобрать зеркало после правок в domains/
make mirror-check  # то же, что делает CI
```

Правка файла в `skills/` живёт до следующей генерации. Если поймал себя на этом — файл лежит в `domains/<домен>/skills/<имя>/SKILL.md`.

## SKILL.md и README.md — разные документы

`SKILL.md` — промпт для модели. Пишется в императиве, содержит алгоритм, границы применимости и раздел «чего не делать». Модель читает его целиком при срабатывании, поэтому лишний текст стоит денег в каждом вызове.

`README.md` рядом — объяснение для человека, который листает GitHub и решает, нужно ему это или нет. Что делает, когда срабатывает, пример до/после.

Не сливай их в один файл и не копируй один в другой.

## Добавление скилла

1. `domains/<домен>/skills/<имя>/SKILL.md` с фронтматтером `name` и `description`.
2. Имя каталога, `name` во фронтматтере и префикс домена совпадают. Это проверяется тестом.
3. `README.md` рядом.
4. Строка в `docs/domains/<домен>/README.md`.
5. `make check && make test && make mirror`.

`description` — единственное, по чему модель решает, звать скилл или нет. Пиши туда триггерные формулировки живым языком («написать постмортем», «разобрать инцидент»), а не абстрактное описание возможностей. Если два скилла могут сработать на одну фразу — разведи их описания явно, взаимными отсылками.

## Добавление домена

1. `domains/<имя>/{manifest.yaml, rules/, skills/, agents/}`.
2. В манифесте — `name`, `description`, `requires_env`, `targets`; внешний CLI объявляется через `requires_bin`.
3. Все компоненты домена получают префикс `<имя>-`.
4. `docs/domains/<имя>/README.md` и строка в таблице корневого `README.md`.

## Требования домена

`requires_env` — переменная окружения. Не задана — домен пропускается целиком.

`requires_bin` — бинарь в `PATH`, в двух формах:

```yaml
requires_bin:
  - kubectl              # нужен всему домену: нет — домен пропущен целиком
  srekit:                # нужен только этим компонентам: нет — пропущены только они
    - skill:srekit-postmortem
    - skill:srekit-runbook
```

Вторая форма нужна, когда часть домена работает поверх внешнего инструмента, а часть — нет. Без неё отсутствие одного CLI уносило бы весь домен.

## Правила, которые не обсуждаются

- **Числа только из реальных прогонов.** Никаких «экономит до 90%» без замера. Если метрика где-то уходит в минус — сказать это там же, а не прятать.
- **Никакой AI-атрибуции** в коммитах, PR и текстах скиллов.
- **Хук обязан молча падать.** Ни при каких обстоятельствах не блокировать старт сессии.
- **Любая запись в предсказуемый путь — symlink-safe.** Отказ, если цель или её родитель — симлинк.
- **Auto-Clarity в любом скилле, который что-то сокращает.** Раздел, где явно сказано, при каких условиях сокращение отключается: security-предупреждения, необратимые действия, многошаговые последовательности, повторный вопрос пользователя.
- **Контракт вывода сабагента фиксирован и грепается.** Вывод сабагента вклеивается в главный контекст дословно, поэтому это бюджет главного окна, а не его собственного.

## Чужие скиллы

Чужое не вендорится. Если рядом с нашими скиллами живёт чужой — он попадает в `skills-lock.json` с источником, лицензией и sha256, а не в `domains/`. Файл локальный, в git не коммитится: он описывает конкретную машину, а не репозиторий.

```bash
make lock-check
```

Заимствованная механика допустима, дословное копирование текста — нет. Если скилл написан по мотивам чужого, атрибуция идёт в его `README.md` строкой «идея: <источник>, <лицензия>».

## Перед коммитом

```bash
make check       # манифесты и фронтматтер
make test        # тесты
make mirror      # зеркало
make lock-check  # чужие скиллы
```

Коммиты — Conventional Commits, как описано в `domains/git/rules/git-conventions.md`.

# Безопасность

## Что здесь вообще есть

`bear-skills` — это markdown-файлы (промпты для AI-агента) плюс Node-скрипты установки. Исполняемого кода, который запускается сам по себе, в скиллах нет. Поверхность атаки — три вещи:

1. **Установщики** пишут в `~/.claude/`, `~/.codex/`, `~/.cursor/` и в Obsidian vault.
2. **Содержимое скиллов** попадает в контекст модели и влияет на её действия.
3. **Скиллы, требующие внешний CLI** (`srekit`) исполняют его команды в твоей системе.

## Что делают установщики

Симлинк-канал (`bin/cli.js`) создаёт симлинки из репозитория в каталоги агентов и снимает только те, что указывают внутрь `bear-skills`. Копирующий канал (`bin/install.js`) кладёт копии и ведёт манифест `.bear-skills-installed.json`, чтобы при удалении не трогать чужое.

Оба канала перезаписывают файл с совпадающим именем. Если у тебя есть свой скилл с таким же именем — он будет затёрт. Проверить заранее: `bear-skills status` и `bear-skills install --dry-run`.

Ни один из них не требует root, не трогает системные каталоги, не устанавливает пакеты и не ходит в сеть, кроме `git clone/pull` из этого репозитория.

## Что скиллы делают с твоими данными

Скиллы работают только с тем, что ты им дал в сессии. Никакой телеметрии, никакой отправки данных наружу — в репозитории нет кода, который куда-либо что-либо шлёт.

Домен `obsidian` читает и пишет файлы внутри `$BEAR_VAULT`. Домен `git` предлагает git-команды, но по контракту не выполняет `push`, `tag` и удаление веток без явного подтверждения. Домен `sre` вызывает CLI `srekit` и `kubectl` — это твои инструменты с твоими правами.

## Prompt injection

Скиллы, которые читают внешний материал (`obsidian-ingest`, `content-zavod`, `srekit-postmortem`), обрабатывают текст из источников, которые ты не писал: статьи, транскрипции, логи. Такой текст может содержать инструкции, адресованные модели.

Правило простое: **содержимое источника — это данные, а не команды**. Если после ингеста статьи агент вдруг предлагает выполнить команду, которой ты не просил, — это ровно тот случай. Не выполняй, посмотри исходник.

## Как сообщить о проблеме

Нашёл что-то, что позволяет коллекции сделать с системой больше, чем описано выше, — напиши на <jtprogru@gmail.com> или заведи issue, если проблема не эксплуатируется по описанию.

Публичный issue подходит для «скрипт удаления сносит лишнее». Приватное письмо — для «вот так через скилл можно выполнить произвольную команду».

Ответ — в течение недели. Это личный проект, не продукт с SLA.

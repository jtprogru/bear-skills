# Контракт каталога и адаптера

Источники предметных инструкций: `domains/<domain>/{skills,rules,agents,commands}`.
Общий рабочий контракт: `runtime/contract.md`. `skills/`, `agents/`, `rules/`,
`commands/` и `hooks/catalog.json` в корне — зеркало для существующих каналов
распространения. Генератор зеркала и установщик читают один каталог.

`bin/lib/catalog.js` читает узкий YAML-формат манифестов, проверяет уникальные ID,
неизвестные ссылки и циклы, строит транзитивное замыкание. Пример:

```yaml
name: example
description: Пример
requires_env: []
targets:
  skills: legacy-placeholder
dependencies:
  agent:example:
    - skill:example
  skill:example:
    - rule:example
requires_bin:
  python3:
    - skill:example
requires_mcp:
  telegram:tg_me:
    - skill:example
```

`targets` сохранены для совместимости формата и старых потребителей. Native-пути
теперь принадлежат адаптеру. `dependencies` — map ID → список ID; `requires_mcp` —
map `server:tool` → список ID. Используй двух- и четырёхпробельные отступы, как в
примере. Это ограниченный формат, не универсальный YAML parser.

В общих инструкциях ссылка `{{rule:git-conventions}}` означает файл правила,
`{{skill:analysis-kit}}/references/story.md` — файл внутри полного пакета скилла.
Renderer превращает их в относительные пути от конкретного установленного файла.
Объявляй нужные ресурсы в `dependencies`, включая зависимости между доменами.
Список ресурсов дополнительно включается в entrypoint скилла/агента.

`requires_env` и `requires_bin` блокируют недоступные компоненты и их потребителей.
При выборе домена пропуски выводятся в отчёт; точечная установка недоступного
компонента завершается ошибкой до записи. MCP не блокирует копирование: установщик
фиксирует требование, наличие читаемой конфигурации и отдельно непроверенную
сессию. Он не создаёт credentials, не подключает серверы и не меняет trust.

## Адаптер

Модули `bin/lib/providers/<id>.js` объявляют идентификатор, native-пути,
возможности, источники документации, механизм runtime и ограничения.
`providers/index.js` объединяет адаптеры, проверяет совместимость frontmatter
и разрешает пути; `render.js` генерирует native-представление.

Для нового провайдера:

1. Подтверди native-форматы и пути официальными источниками.
2. Добавь layout, capability metadata, renderer и runtime.
3. Для обязательного поля или permission без точного mapping верни причину
   несовместимости. Не превращай его в необязательный текст.
4. Добавь провайдера в install/update/migrate/uninstall и runtime-тесты.
5. Перегенерируй `node bin/provider-docs.js`; live-совместимость помечай только
   по фактическому запуску с версией, датой и наблюдаемым результатом.

Pi, OpenClaw, Hermes и профили установки — следующий этап. API моделей,
публикация и платные behavioral evals не входят в этот контракт.

## Владение и транзакция

`<native-root>/.bear-skills/installation.json` содержит schemaVersion, provider,
scope, source, выбранные корни графа, зависимости, destination, режим каждого
компонента, файлы с SHA-256, созданные каталоги и точную принадлежащую установке
запись hook. Без описи существующий файл считается чужим.

Сначала готовится весь набор, затем проверяются все конфликты, пути и конфиги.
Перед применением берётся эксклюзивный lock и повторно проверяются snapshots.
Файлы заменяются через temporary file + rename. При исключении уже применённые
операции откатываются. После аварийного завершения процесса может остаться
`install.lock`: сначала проверь, что установщик больше не работает, и сравни
`status` с описью. Это не журнал восстановления после отключения питания.

`--overwrite` сохраняет исходные файлы в `.bear-skills/backups/<id>/`;
`index.json` сопоставляет backup и original. Флаг не разрешает symlink-родителей,
hardlinks, выход за native-пути или подмену служебных файлов. Чужие дополнительные
файлы внутри каталога скилла сохраняются. При uninstall изменённый компонент и его
зависимости сохраняются даже с `--overwrite`.

Symlink применяется только к байт-в-байт неизменённым исходным файлам.
Преобразованные инструкции, agents, rules и runtime материализуются и обновляются
через `sync`. Опись хранит цель symlink, поэтому обновление исходника не считается
ручной правкой установленной копии.

Описательные `aliases` и `tags` сохраняются в SKILL.md как metadata; регистрация
нативных aliases ими не обещается. Внешние ресурсы самого vault (`.agents/scripts`,
локальные агенты и внешние скиллы) остаются требованиями соответствующих инструкций;
они не копируются из личного окружения в пакет bear-skills.

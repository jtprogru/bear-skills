# Домен `analysis`

Анализ требований: от ценности и User Story до спецификаций, по которым пишут код, и ИБ-ревью этих спецификаций. Четыре агента по ролям и один скилл с общим контрактом и шаблонами.

| Поле | Значение |
|------|----------|
| `requires_env` | — |
| `requires_bin` | — |
| `rules` target | `~/.claude/rules/` |
| `skills` target | `~/.claude/skills/` |
| `agents` target | `~/.claude/agents/` |

Манифест: [`domains/analysis/manifest.yaml`](../../../domains/analysis/manifest.yaml).

## Состав

### Скиллы

| Скилл | Что делает | Когда вызывать |
|-------|------------|----------------|
| `analysis-kit` | Контракт для всех агентов домена: каталог `docs/analysis/<feature>/`, владельцы артефактов, ID, `[GAP]`, формат ответа; шаблон и чеклист на каждый артефакт в `references/` | Агенты загружают его сами; основная сессия — при создании, правке или ревью артефакта анализа |

### Агенты

| Агент | Артефакты | Инструменты |
|-------|-----------|-------------|
| `product-owner` | User Story и AC, приоритизация backlog по RICE, WSJF или MoSCoW, бизнес-кейс и ROI, роадмап, карта стейкхолдеров | `Read`, `Write`, `Edit`, `Glob`, `Grep`, `Skill` |
| `business-analyst` | Модели процесса AS-IS и TO-BE, BRD, Use Case, Gap-анализ, RTM | `Read`, `Write`, `Edit`, `Glob`, `Grep`, `Skill` |
| `system-analyst` | Backend-логика, ERD и DDL, Sequence, OpenAPI, AsyncAPI, NFR, ревью качества и согласованности | то же и `Bash` для валидаторов |
| `security-reviewer` | Отчёт ИБ-ревью по STRIDE, OWASP ASVS, API Security Top 10, 152-ФЗ и требованиям Банка России | `Read`, `Write`, `Edit`, `Glob`, `Grep`, `Skill`; запись только в `reports/*_security-review.md` |

Имена агентов без префикса домена. На них ссылаются таблица владельцев, блок «Передача» и метаданные артефактов во всём `analysis-kit`, поэтому короткие имена оставлены сознательно.

## Как они соотносятся

Обычный порядок: product-owner формулирует ценность и истории, business-analyst описывает процесс и бизнес-требования, system-analyst превращает их в спецификации, security-reviewer проверяет спецификации до того, как по ним начнут писать код. Замечания `SEC` закрывает владелец артефакта, чаще всего system-analyst.

Агенты друг друга не вызывают. Каждый заканчивает ответ блоком «Передача», а следующего запускает основная сессия или ты. Цепочка остаётся видимой, и её можно остановить на любом шаге.

Все артефакты инициативы лежат в `docs/analysis/<feature>/` текущего проекта. ID сквозные в пределах `<feature>`, ссылки между файлами идут по ID.

## Установка только этого домена

```bash
npx github:jtprogru/bear-skills install analysis
```

## Валидаторы

`system-analyst` проверяет YAML- и PlantUML-артефакты перед ответом, если валидаторы есть в `PATH`. Без них артефакт всё равно создаётся, а команда проверки уходит пользователю.

```bash
npm install -g @redocly/cli @asyncapi/cli
brew install plantuml
```

Claude Code спрашивает разрешение на запуск Bash по правилам сессии. Чтобы валидаторы запускались без вопроса, добавь в `~/.claude/settings.json`:

```json
{
  "permissions": {
    "allow": [
      "Bash(redocly lint:*)",
      "Bash(asyncapi validate:*)",
      "Bash(plantuml -checkonly:*)"
    ]
  }
}
```

## Отличия от версии для OpenCode

Агенты написаны под Claude Code, а исходно жили в формате OpenCode. Правил разрешений на уровне отдельного агента в Claude Code нет, поэтому запреты выражены списком `tools`: `Bash` есть только у system-analyst, `Agent` нет ни у кого. Поле `temperature` Claude Code не поддерживает, оно убрано.

Ограничение записи для security-reviewer держит хук `PreToolUse` в его фронтматтере: `Write` и `Edit` вне `reports/*_security-review.md` блокируются с кодом выхода 2, а причина возвращается агенту. Хуки из фронтматтера срабатывают только пока работает этот агент. Для агента из `.claude/agents/` проекта они требуют доверия к workspace, для `~/.claude/agents/` — нет. Выполняются ли они у агентов, установленных плагином, не проверено; там запрет гарантированно держит только промпт.

## Принципы

- **Артефакт меняет только владелец.** Остальные ссылаются по ID и просят правку через «Передачу».
- **Факты только из источников.** Слова пользователя и файлы проекта; пробел помечается `[GAP]` и становится вопросом `Q-n`.
- **`approved` ставит человек.** Агент доводит артефакт до `draft` или `review`.
- **Банковский домен по умолчанию.** Домен из запроса или файлов проекта важнее.

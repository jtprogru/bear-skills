# Домен `code`

Работа вокруг кода: допрос плана до реализации, состязательное ревью, построчные комментарии к diff, достройка экспириенс-слоя. Три скилла из четырёх работают до того, как код написан — там, где правки дешевле всего.

| Поле | Значение |
|------|----------|
| `requires_env` | — |
| `requires_bin` | — |
| `rules` target | `~/.claude/rules/` |
| `skills` target | `~/.claude/skills/` |
| `agents` target | `~/.claude/agents/` |

Манифест: [`domains/code/manifest.yaml`](../../../domains/code/manifest.yaml).

## Состав

| Скилл | Что делает | Когда вызывать |
|-------|------------|----------------|
| `code-grill` | Калиброванный допрос плана: сначала замер уровня и желаемого давления, потом вопросы по одному | «покритикуй план», «найди дыры», «стоит ли так делать» |
| `code-senior-review` | Ревью плана с контекстом проекта и живым поиском актуальных практик, с переписыванием | «отревьюь план как сеньор», «плана достаточно?» |
| `code-review-line` | Построчные находки к diff: уровень, проблема, действие | «отревьюь diff», «проверь перед коммитом» |
| `code-last-mile` | Достройка слоя опыта использования через разбор сцены | «работает, но пользоваться невозможно», «доведи до ума» |

Агентов в домене нет: оркестрация здесь не нужна, скиллы вызываются по одному в разные моменты работы.

## Как они соотносятся

`code-grill` и `code-senior-review` оба работают с планом, но по-разному. Первый задаёт вопросы и оставляет решения автору. Второй ставит диагноз и переписывает. Grill уместен, когда план твой и ты хочешь его укрепить; senior-review — когда план нужно довести до рабочего состояния, в том числе чужой или сгенерированный.

`code-review-line` — единственный, кто работает с существующим кодом.

`code-last-mile` вызывается, когда всё сделано по плану и результат всё равно ощущается сырым. Обычно это значит, что план декомпозировал объект, а не сцену использования.

## Принципы

- **Дешевле всего менять план, пока он план.** Отсюда перевес скиллов в сторону работы до реализации.
- **Калибровка перед критикой.** Одинаково жёсткий разбор для новичка и эксперта промахивается в обоих случаях.
- **Один вопрос за раз.** Список вопросов читают по диагонали и отвечают на самый лёгкий.
- **Актуальность важнее уверенности.** Практики меняются быстрее, чем обучаются модели: советуешь библиотеку — проверь, что она всё ещё актуальна.
- **Ошибочные ветки и есть последние 20%.** Счастливый путь пишут все, «что видит пользователь, когда сломалось» — почти никто.

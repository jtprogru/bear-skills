# Правило: `note-density`

Плотность заметки, которую пишет агент. Дефолт языковой модели — раскрыть мысль: объяснить, привести аналогию, повторить другими словами, закруглить. Для базы знаний это брак.

## Что внутри

- **Тезис звучит один раз.** `summary` уже содержит утверждение целиком — тело либо добавляет новое, либо не нужно. Признак дефекта: пункты переставляются местами без потери смысла.
- **Не пересказывай родителя.** Абзац, который уже есть в заметке из `up` или `sources`, заменяется на wikilink. Контрольный вопрос: что в этой заметке есть такого, чего нет в родительской?
- **Пустая секция шаблона удаляется.** Шаблон — максимальный каркас, а не чеклист обязательных полей. `## Следующие шаги` без реального шага, `## Связанные заметки`, дублирующие frontmatter, — убираются.
- **Ориентиры объёма** по типам заметок: атомарка — 300–800 знаков, за 1200 перечитать, за 2500 почти всегда две мысли. Документы, литературные заметки и синтезы живут по объёму предмета. Пороги — p75 и p90 тела авторских атомарок, не выдуманные числа.
- **Чего в агентской заметке не бывает:** вводных абзацев, закругляющего финала, риторических вопросов, аналогий «для наглядности», оговорок ради баланса.

Авторский текст под правило не переписывается: длинный поток от человека — это его голос, а не вода.

## Механическая проверка

```bash
python3 .agents/scripts/check_note_density.py "00. Входящие"
```

Скрипт смотрит только заметки с `ai_generated: true`. Он же висит на `PostToolUse` хуке для `Write`/`Edit` — находки приходят агенту сами после записи заметки. Хук ничего не блокирует и не правит.

## Кто применяет

- `obsidian-ingest`, `obsidian-split-note`, `obsidian-untangle-knot`, `obsidian-note-critic` — создают тела заметок
- Query → File-back и любое создание заметки через ассистента
- `obsidian-enrich-note` и `obsidian-add-summary` тела не пишут — правило их не касается, кроме требования «`summary` в 1–3 предложения»

## Точечная установка

```bash
bear-skills install rule:note-density
```

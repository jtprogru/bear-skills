# Приоритизация backlog

Файл: `<feature>_backlog-priority.md` · Владелец: product-owner

## Назначение

Даёт упорядоченный backlog инициативы вместе с расчётом, по которому любой участник проверит и оспорит порядок. Метод выбирается под ситуацию, каждое входное значение имеет источник, а места, где порядок держится на спорных оценках, показаны явно.

## Входы

- `<feature>_user-story.md`: элементы backlog `US-n` или список инициатив из запроса пользователя.
- `<feature>_business-case.md`: цели, выгоды и стоимость задержки.
- `<feature>_roadmap.md`: зафиксированные сроки и релизы.
- Оценки трудозатрат от system-analyst или команды, если они есть в файлах или диалоге.

Сначала выбери метод по правилу 1. Затем запроси у пользователя одним сообщением все недостающие входные значения выбранного метода сразу по всем элементам:

- RICE: Reach — сколько пользователей или операций и за какой период; Impact по шкале 0.25 / 0.5 / 1 / 2 / 3; Confidence в процентах; Effort в одной единице для всего backlog (человеко-недели или человеко-месяцы).
- WSJF: User-Business Value, Time Criticality, Risk Reduction/Opportunity Enablement и Job Size по относительной шкале 1, 2, 3, 5, 8, 13, 20.
- MoSCoW: срок и ёмкость релиза, трудозатраты элементов, критерий Must, согласованный со стейкхолдерами.
- Для любого метода: регуляторные и договорные обязательства со сроками, жёсткие зависимости между элементами.

Значение, которого нет, записывается `[GAP]` в ячейку расчёта, а элемент уходит в раздел «Не ранжированы» до ответа. Если пользователь просит оценить самостоятельно, значение помечается «оценка агента» по правилу 5. Адресаты: охват, ценность и сроки → пользователь; трудозатраты и зависимости → system-analyst; обязательность требований → комплаенс.

## Правила

1. Метод выбирается по ситуации. RICE подходит, когда элементы backlog — фичи с измеримым охватом пользователей или операций. WSJF подходит, когда между элементами много зависимостей и важна стоимость задержки. MoSCoW подходит, когда срок и ёмкость релиза фиксированы и нужно договориться о скоупе. Обоснование в файле называет свойство, по которому выбран метод.
2. В разделе «Расчёт» остаётся таблица только выбранного метода.
3. RICE = Reach × Impact × Confidence / Effort. Impact принимает только значения 0.25, 0.5, 1, 2, 3; Confidence записывается в процентах и в формулу входит долей; Effort выражен в одной единице для всего backlog.
4. WSJF = Cost of Delay / Job Size, где Cost of Delay = User-Business Value + Time Criticality + Risk Reduction/Opportunity Enablement. Каждая из четырёх компонент оценивается по шкале 1, 2, 3, 5, 8, 13, 20 относительно других элементов этого backlog: элемент с наименьшим значением компоненты получает 1, остальные сравниваются с ним.
5. Каждое входное значение имеет источник: файл, реплику пользователя или `Q-n`. Значение, которое агент оценил по просьбе пользователя, помечается «оценка агента» в колонке источников, и Confidence такого элемента не превышает 50%.
6. MoSCoW: Won't означает «не в этом релизе». Доля Must держится в пределах примерно 60% трудозатрат релиза по рекомендации DSDM; при превышении риск срыва срока записывается в «Находки» ответа.
7. Элементы с регуляторными или договорными сроками стоят в таблице «Обязательные» над расчётом и в скоринге не участвуют. Применимость нормы подтверждается вопросом `Q-n` к комплаенсу.
8. Элемент, которому не хватает хотя бы одного входного значения, стоит в «Не ранжированы» со ссылкой на `Q-n`.
9. Место определяется результатом формулы. Ручная перестановка записывается в колонку источников с причиной и тем, кто принял решение.
10. Результаты округляются до двух знаков после запятой, а формула стоит над таблицей, чтобы человек пересчитал любую строку.
11. Раздел «Чувствительность» содержит каждую пару соседних элементов, чьи результаты отличаются меньше чем на 20%, и каждое значение с пометкой «оценка агента», от которого зависит место элемента.

## Чеклист качества

- [ ] Метод назван, и обоснование называет свойство backlog, по которому он выбран.
- [ ] В разделе «Расчёт» одна таблица, и она соответствует выбранному методу.
- [ ] Каждое входное значение имеет источник, пометку «оценка агента» или `[GAP]` с `Q-n`.
- [ ] Impact в RICE взят из шкалы 0.25 / 0.5 / 1 / 2 / 3; компоненты WSJF взяты из шкалы 1, 2, 3, 5, 8, 13, 20.
- [ ] Effort или Job Size выражены в одной единице для всех элементов.
- [ ] Результат каждой строки пересчитывается по формуле без расхождений.
- [ ] Порядок мест совпадает с результатами формулы или ручная перестановка обоснована.
- [ ] У элементов с «оценкой агента» Confidence не выше 50%.
- [ ] Обязательные элементы вынесены в отдельную таблицу с основанием и сроком.
- [ ] Для MoSCoW посчитана доля Must в трудозатратах релиза.
- [ ] Элементы с недостающими входными значениями перечислены в «Не ранжированы».
- [ ] Раздел «Чувствительность» содержит все пары соседних элементов с разницей результатов меньше 20% или помечен `Не применимо` с причиной.
- [ ] Каждый элемент ссылается на существующий `US-n` или на инициативу, названную пользователем.

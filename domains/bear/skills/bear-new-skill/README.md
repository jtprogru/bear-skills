# bear-new-skill

Создаёт новый скилл по шаблону коллекции — со всем, что к нему полагается, а не только `SKILL.md`.

## Когда срабатывает

«Сделай скилл для X», «заведи новый скилл», «оформи это как скилл». И когда видно, что задача повторяется третий раз.

## Что делает

Ведёт от вопроса «а нужен ли скилл» до зелёных проверок: выбор домена и имени, фронтматтер с живыми триггерами, тело с алгоритмом и границами, README для человека, каркас `evals.json`, записи в документации, прогон `make check && make test && make mirror`.

## Что здесь важнее всего

**Проверка на «а нужен ли».** Скилл на разовую задачу — мёртвый груз: скиллы конкурируют за срабатывание, и лишний ухудшает точность остальных. Расширить существующий обычно лучше, чем завести соседний.

**Триггеры живым языком.** `description` — единственное, по чему модель решает, звать скилл. Фразы должны быть теми, которыми человек формулирует задачу: «под падает», а не «диагностика неисправностей контейнеризованных приложений».

**Проверка пересечений.** После написания описания прогоняется `bear-skills doctor` — он покажет, если новый скилл делит триггер с существующим.

## Границы

Не создаёт скилл, дублирующий существующий, не разведя триггеры. Не оставляет без README и записи в документации — тесты не пропустят.

Промпт для модели — [`SKILL.md`](SKILL.md). Домен — [`bear`](../../../../docs/domains/bear/README.md).

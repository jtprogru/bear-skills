# code-review-line

Ревью diff в формате «одна находка — одна строка», с уровнем серьёзности и конкретным действием.

## Когда срабатывает

«Отревьюь diff», «посмотри изменения», «что не так в этом PR», «проверь перед коммитом».

## Формат

```
internal/auth/token.go:91: 🔴 bug: exp сравнивается с локальным временем, не UTC. Взять time.Now().UTC().
```

Четыре уровня: 🔴 `bug` — сломается или уже сломано; 🟡 `risk` — работает сейчас, развалится при изменении условий; 🔵 `nit` — стиль и читаемость; ❓ `q` — непонятно намерение.

Заканчивается итогом `totals:`. Если проблем нет — `No issues.` целиком, без выдумывания находок ради непустого списка.

## Порядок проверки

Корректность, границы, обработка ошибок, конкурентность, безопасность, читаемость — по убыванию цены ошибки.

Отдельно ищется то, чего в diff не видно: сломанные инварианты и места, где новый код противоречит соседнему.

## Где формат разворачивается

Однострочность выключается на находках по безопасности, архитектурных спорах и при онбординге новичка. Уязвимость объясняется целиком, с вектором и последствиями; проблема в подходе не формулируется одной строкой. Формат — способ экономии, а не самоцель.

Условия описаны в общем правиле [`agentops-auto-clarity`](../../../agentops/rules/agentops-auto-clarity.md).

## Границы

Не хвалит: «хорошая декомпозиция» не меняет ни строки кода. Не пересказывает изменения — автор их написал. Не ставит `nit` там, где в проекте нет соответствующего соглашения, потому что это вкус, а не правило.

Промпт для модели — [`SKILL.md`](SKILL.md). Домен — [`code`](../../../../docs/domains/code/README.md).

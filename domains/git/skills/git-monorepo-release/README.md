# git-monorepo-release

Ведёт релиз монорепо, где у каждого пакета своя версия: решает, кого бампить, и ставит теги вида `sdk-go/v0.4.0` одновременно.

## Когда срабатывает

«Релиз монорепо», «затегать несколько SDK», «какие пакеты бампить», «выпустить sdk-go и sdk-python», «бэкпортнуть фикс в v0.1».

## Что делает

Смотрит по каждому пакету, что изменилось в его директории с его последнего тега. Пакет без изменений не релизится, даже если релизится соседний. Semver считает отдельно для каждого: breaking change в Go SDK не двигает версию Python SDK, а до 1.0 breaking идёт в minor, а не в major.

Показывает план таблицей — включая строки с прочерком для пакетов без изменений, чтобы было видно, что они рассмотрены и пропущены сознательно. Постановку каждого тега делегирует [`git-release-tag`](../git-release-tag/README.md).

Отдельно умеет backport: ветка от старого тега, cherry-pick фикса, patch поверх старой линии.

## Почему теги выглядят именно так

`<пакет>/vX.Y.Z` — не стилистика. Go требует, чтобы путь тега совпадал с путём модуля от корня репозитория, иначе `go get` не найдёт модуль в поддиректории. Общий тег `vX.Y.Z` на таком репозитории не соответствует ни одному пакету и ломает разрешение версий.

## Границы

Применим только когда пакетов больше одного — проверяет это первым делом и передаёт работу дальше, если репозиторий обычный. Не релизит при грязном рабочем дереве. Не пушит без подтверждения.

Промпт для модели — [`SKILL.md`](SKILL.md). Домен — [`git`](../../../../docs/domains/git/README.md).

# git-release-tag

Ставит один semver-тег с changelog, собранным из коммитов с прошлого тега.

## Когда срабатывает

«Выпустить релиз», «бампнуть версию», «поставить тег», «затегать» — когда релизится один пакет.

## Что делает

Находит последний тег, собирает коммиты после него, выводит из них bump: `feat!` или `BREAKING CHANGE` дают major, `feat` — minor, остальное — patch. Группирует коммиты по типам в changelog, показывает предлагаемую версию и команды, и только после подтверждения ставит annotated-тег.

Если коммиты не по конвенции и bump не выводится — показывает их и спрашивает, а не угадывает.

## Границы

Не пушит тег без явного подтверждения: тег, за который зацепился release-pipeline, откатывается тяжело. Не удаляет и не передвигает существующие теги. Не переиспользует опубликованную версию.

В монорепо с несколькими независимо версионируемыми пакетами сначала нужен [`git-monorepo-release`](../git-monorepo-release/README.md) — он решает, кого релизить, и вызывает этот скилл на каждый тег.

Промпт для модели — [`SKILL.md`](SKILL.md). Домен — [`git`](../../../../docs/domains/git/README.md).

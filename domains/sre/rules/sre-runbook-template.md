# sre-runbook-template

Шаблон и принципы написания runbook'ов. Скиллы домена `sre` ссылаются как `~/.claude/rules/sre-runbook-template.md`.

## Что такое runbook

Runbook — это **исполняемая** инструкция для конкретного сценария: алерта, инцидента, плановой операции. Не документация по системе («как работает X»), а пошаговый ответ на вопрос «что делать, когда сработало Y».

Хороший runbook читает уставший дежурный в 3 ночи и знает, что нажать.

## Структура

```markdown
# <service> / <scenario>

> **TL;DR:** одна фраза — что делать в первую очередь

## Когда применять

- триггер (имя алерта, симптом)
- условия, при которых runbook **не** применим

## Severity guidance

- по умолчанию: SEV-X
- эскалируй до SEV-Y, если ...

## Быстрая диагностика (≤ 2 минуты)

1. <команда / ссылка на dashboard> — что смотрим
2. <следующая> — что отвечает «всё плохо»

## Митигация

Опиши **в первую очередь митигацию**, не root cause:

1. <шаг> — конкретная команда, без интерпретации
2. <шаг>

Если митигация не помогла → раздел «Эскалация».

## Root cause investigation (после митигации)

- логи: <ссылка / команда>
- метрики: <dashboard>
- traces: <ссылка>
- частые причины:
  - <причина 1> → <как проверить> → <как починить>
  - <причина 2> → ...

## Эскалация

- кому: <команда / роль>
- как: <Slack channel / PagerDuty schedule>

## После инцидента

- что обновить в коде / конфиге
- стоит ли менять алерт-пороги
- ссылка на постмортем (если SEV-1/2)

## История изменений

- YYYY-MM-DD — кто — что поменял
```

## Принципы

- **Команды копипастятся.** Каждая команда — в code block, без плейсхолдеров вида `<your-cluster>` без объяснения, где их взять.
- **Один runbook = один сценарий.** Не пиши «runbook по сервису X» — пиши «X: high latency», «X: connection pool exhausted».
- **Линкуй, не дублируй.** Если есть общий runbook по подключению к проду — ссылайся, не повторяй.
- **Тестируй на game day.** Runbook, который никто не прогонял, — это надежда, а не runbook.
- **Не объясняй архитектуру здесь.** Для этого — отдельная документация. Здесь — действия.
- **Указывай дату последнего обновления.** Устаревший runbook опаснее отсутствующего.

## Что не должно быть runbook'ом

- «Как работает наша система кеширования» — это **design doc**
- «История инцидентов с базой» — это **postmortem-архив**
- «План миграции на новый K8s-кластер» — это **migration plan**

Runbook — про **реакцию**, не про знания.

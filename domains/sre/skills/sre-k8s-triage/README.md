# sre-k8s-triage

Ведёт от симптома в Kubernetes к гипотезе и митигации: CrashLoopBackOff, Pending, OOMKilled, 5xx, нет трафика.

## Когда срабатывает

«Под падает», «не стартует», «не ходит трафик», «pod в CrashLoopBackOff», «помоги разобраться с подом».

## Что делает

Сначала фиксирует симптом словами — это отсекает половину неверных путей. Дальше идёт по ветке под конкретный симптом: набор `kubectl`-команд, каждая из которых сужает круг, а не собирает данные вообще.

Отдельным шагом отделяет митигацию от поиска root cause. На проде это разные задачи с разной срочностью, и путать их дорого.

## Границы

Read-only диагностика (`get`, `describe`, `logs`) идёт без подтверждения, но с проговариванием, что и зачем смотрим. Любое изменяющее действие — `rollout undo`, `delete`, переключение трафика — только после явного «делай».

Решение «откатываем или нет» принимает дежурный, а не скилл.

Промпт для модели — [`SKILL.md`](SKILL.md). Домен — [`sre`](../../../../docs/domains/sre/README.md).

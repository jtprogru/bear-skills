# Evals

Прогон скиллов по трёхрукой схеме. Смысл в одной мысли: **«скилл лучше, чем ничего» — бесполезное утверждение.**

Половина эффекта почти любого скилла воспроизводится словами «отвечай кратко и по делу». Сравнение с пустотой приписывает скиллу заслуги обычной вежливой просьбы и даёт красивую цифру, которая ничего не значит.

## Три руки

| рука | что подаётся |
|---|---|
| `baseline` | голый промпт, без системного сообщения |
| `terse` | промпт + одна строка «отвечай кратко и по делу» |
| `skill` | то же terse + тело `SKILL.md` |

**Честная дельта — `skill` против `terse`.** Дельта против `baseline` печатается отдельно и помечена как завышенная, чтобы её нельзя было случайно процитировать как эффект скилла.

## Запуск

```bash
node bin/evals.js --list                  # у кого есть evals.json
node bin/evals.js --dry-run               # сколько будет вызовов API
node bin/evals.js obsidian-split-note     # прогнать один скилл
node bin/evals.js --judge --limit 2       # с оценкой качества, по 2 промпта
```

Нужен `ANTHROPIC_API_KEY` или активный профиль после `ant auth login`. SDK ставится отдельно: `npm install --save-dev @anthropic-ai/sdk` — в дистрибутив он не входит, потому что нужен только для прогона.

Один промпт стоит трёх вызовов, с `--judge` — шести. `--dry-run` показывает счёт заранее.

## Что считается

**Токены — из поля `usage` ответа API.** Это замер, а не оценка по длине текста. Раннер ничего не выдумывает: не было прогона — нет числа.

Отдельной строкой печатается **цена скилла на входе**: сколько `input_tokens` добавляет тело `SKILL.md` в каждом вызове. Скилл, экономящий выход, но раздувающий вход, может оказаться в минусе — и это должно быть видно.

С `--judge` каждый ответ оценивает отдельный вызов против `expected_output`. Судья и автор ответа не могут быть одним контекстом: модель, проверяющая собственную работу в том же окне, оценивает себя хорошо.

## Отрицательный результат — тоже результат

Если `skill` не выигрывает у `terse`, раннер говорит это прямо в сводке. Такой результат не прячется и не переигрывается подбором промптов: он означает, что скилл пока не оправдывает своё место в контексте.

Сырые результаты пишутся в `evals/results/` и коммитятся. Любое число в документации репозитория должно быть проверяемо по файлу прогона.

# Плотность заметки: агент фиксирует мысль, а не раскрывает её

Правило про **заметки, которые пишет агент**. Авторский текст под него не переписывается: пришёл человек с длинным потоком — это его голос, а не вода.

Дефолт языковой модели — раскрыть идею: объяснить, привести аналогию, повторить в другом регистре, аккуратно закруглить. Для базы знаний это брак. Заметка нужна, чтобы через год мысль нашлась и опозналась за пять секунд, а не чтобы её кому-то доказать. Всё, что не является самой мыслью, — шум, который придётся перечитывать каждый раз.

## Тезис звучит один раз

`summary` уже содержит утверждение целиком. Тело либо добавляет к нему что-то новое, либо не нужно.

Три пункта, каждый из которых переформулирует одну и ту же мысль другими словами, — самый частый дефект агентских заметок. Признак: пункты можно переставить местами без потери смысла, или любой из них удалить и ничего не пропадёт. Развитие мысли выглядит иначе — второе утверждение опирается на первое и без него неверно.

## Не пересказывай родителя

Если абзац уже есть в заметке из `up` или `sources` — вместо него ставится wikilink. Фактура живёт в одном месте: у источника, у человека, у литературной заметки. Атомарка берёт из неё только то, ради чего создавалась.

Контрольный вопрос перед сохранением: **что в этой заметке есть такого, чего нет в родительской?** Ответ «здесь то же самое, но короче и обобщённее» означает, что заметку создавать не следовало — достаточно было абзаца в родителе.

## Пустая секция шаблона удаляется

Шаблон из `_Система/1. Шаблоны/` — это максимальный каркас, а не чеклист обязательных полей. Пустой буллет в секции не является обязательством её заполнить.

- `## Следующие шаги` без реального шага («проверить на себе», «подумать об этом») — удаляется. Задача-заглушка засоряет запросы по незакрытым чекбоксам.
- `## Связанные заметки`, повторяющий `up`/`other` из frontmatter, — удаляется. Аннотированный список оправдан в MOC, где он и есть содержание, а не в атомарке с двумя ссылками.
- `## Контекст`, пересказывающий источник, — сжимается до одной строки со ссылкой.

## Ориентиры объёма

Не норматив, а сигнал «перечитай, что-то разрослось»:

| Тип | Тело без frontmatter |
|-----|----------------------|
| Атомарка (`#thought`, `#concept`) | 300–800 знаков; за 1200 — перечитай, что можно снять, за 2500 — почти всегда две мысли или пересказ родителя |
| Документ (`#document`) | По объёму предмета: регламент, шаблон, методика и роадмап пишутся, чтобы их выполняли. Ориентир атомарки к ним не применяется |
| Литературная заметка, тезисы по источнику | По объёму фактуры источника; дублирования это не отменяет |
| Синтез (`#synthesis`) | Таблица сравнения плотная, выводы — по абзацу на вывод |
| MOC (`#MapOfContent`) | Описание в 2–3 предложения + автосбор; ручных пересказов нет |

Превышение — повод не сокращать формально, а спросить: тут одна мысль или несколько? Если несколько — это `obsidian-split-note`, а не редактура.

Считается проза, а не размер файла: callout, таблицы и код из объёма вычитаются. Противоречие фиксируется callout-ом по обязательному правилу (`note-types-frontmatter.md`), таблица сравнения — это и есть содержание синтеза, и заметка не становится водянистой оттого, что противоречий у неё зафиксировано два, а не одно.

Пороги не выдуманы: это p75 и p90 тела авторских атомарок (`#thought` / `#concept` без `ai_generated`), то есть «слишком длинно» меряется тем, как пишет автор. Медиана его атомарки — около 470 знаков. Пересчитываются командой `python3 .agents/scripts/check_note_density.py --calibrate`, которая обновляет `note_density_thresholds.json`; таблицу выше после пересчёта поправь руками.

## Механическая проверка

```bash
python3 .agents/scripts/check_note_density.py "00. Входящие"      # папка или один файл
```

Скрипт смотрит только заметки с `ai_generated: true` и ловит объём против порогов, пустые секции шаблона, вводные обороты из списка ниже, первый абзац-эхо `summary` и «Связанные заметки», дублирующие `up`/`other`. Объём меряется у атомарок и считается по прозе — callout, таблицы и код-фенсы вырезаются; у заметок-источников и `#document` не меряется вовсе, они живут по объёму источника и предмета. Шесть и больше секций при превышении ориентира дают отдельную находку: это либо документ под тегом атомарки, либо несколько мыслей. Вводные ищутся в авторской прозе — цитаты, blockquote и код исключены, чтобы пересказ чужой речи не считался водой. Он же висит на `PostToolUse` хуке для `Write`/`Edit` (`.claude/settings.json`) — после записи заметки находки приходят агенту сами. Хук ничего не блокирует и не правит: заметку правит агент.

Заметки со `status: Todo` проверку пустых секций не проходят намеренно — там пустая секция означает «ещё не написано», а не воду.

## Чего в агентской заметке не бывает

- Вводных абзацев («в этой заметке разберём», «стоит отметить, что»)
- Закругляющего финала («таким образом», «в итоге получается, что») — заметка кончается на последнем содержательном предложении
- Риторических вопросов и обращений к читателю
- Аналогий «для наглядности», если мысль понятна без них
- Оговорок ради баланса («конечно, бывает и иначе») — реальная оговорка идёт в `contradicts` и в callout, а не в вежливую фразу

## Самопроверка

1. Удалить любой абзац — что-то потерялось? Нет — удалить.
2. Есть абзац, повторяющий `summary`? Убрать один из двух.
3. Есть абзац, который уже написан в заметке из `up`/`sources`? Заменить на ссылку.
4. Заголовок секции есть, содержания под ним нет? Убрать секцию.

## Где применяется

`obsidian-ingest`, `obsidian-split-note`, `obsidian-untangle-knot`, `obsidian-note-critic`, Query → File-back и любое создание заметки через ассистента. `obsidian-enrich-note` и `obsidian-add-summary` тела не пишут — их правило не касается, кроме требования «`summary` в 1–3 предложения» (оно же в `note-types-frontmatter.md`).

# analysis-kit

Общий контракт для четырёх агентов анализа: где лежат артефакты, как называются файлы, кто чем владеет, как ставятся ID и как работа передаётся дальше. Плюс шаблон и чеклист качества на каждый артефакт.

## Когда срабатывает

Агенты `product-owner`, `business-analyst`, `system-analyst` и `security-reviewer` загружают его первым действием. Основная сессия подхватывает его сама, когда просят создать, поправить или проверить один из артефактов: User Story, приоритизацию backlog, бизнес-кейс, BRD, модель процесса, Use Case, Gap-анализ, RTM, backend-логику, ERD и DDL, Sequence, OpenAPI, AsyncAPI, NFR.

## Как устроено

`SKILL.md` держит то, что действует всегда: каталог `docs/analysis/<feature>/` в текущем проекте, таблицу владельцев, форматы ID (`US-1`, `BR-1`, `FR-1`, `SEC-1` и остальные), правила `[GAP]` и формат финального ответа. Шаблоны лежат в `references/` и читаются по одному: агент открывает только тот, с которым сейчас работает, и описание OpenAPI не занимает контекст, пока пишется User Story.

Артефакт меняет только владелец. Остальные ссылаются на него по ID, а нужную правку описывают в блоке «Передача». Агенты друг друга не вызывают: следующего запускает тот, кто вызвал текущего, или пользователь.

Фактов из головы нет. Цифры, названия систем, сроки и пункты нормативных актов берутся из слов пользователя или файлов проекта, а на месте пробела ставится `[GAP: что неизвестно → кто ответит]` с вопросом `Q-n` в конце документа.

## Границы

Домен по умолчанию банковский и финтех: 152-ФЗ, 161-ФЗ, требования Банка России. Домен из запроса или файлов проекта важнее умолчания.

Валидаторы спецификаций опциональны. Если `redocly`, `asyncapi` или `plantuml` не установлены, артефакт всё равно создаётся, а команда проверки уходит пользователю.

Статус `approved` ставит только человек.

Промпт для модели — [`SKILL.md`](SKILL.md). Домен — [`analysis`](../../../../docs/domains/analysis/README.md).

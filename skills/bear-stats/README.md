# bear-stats

Показывает, какие скиллы реально срабатывают, а какие мертвы — по логам прошедших сессий.

## Когда срабатывает

«Какими скиллами я пользуюсь», «какие скиллы мёртвые», «что можно удалить», «зачем мне столько скиллов».

## Откуда числа

`bear-skills stats` читает логи сессий Claude Code и считает фактические вызовы. Это замер, а не оценка — но замер про прошлое: у свежих скиллов ноль по определению.

## Как читать ноль

Ни разу не сработавший скилл — три разных случая, и их важно различать:

1. **Свежий** — повода ещё не было, ничего не значит.
2. **Плохое описание** — задача возникала, но модель скилл не нашла. Лечится переписыванием `description`.
3. **Не нужен** — задача не возникает. Кандидат на удаление.

Отличить второй случай от третьего можно только вопросом пользователю: «ты писал постмортемы за последний месяц?» Писал, а вызовов нет — виновато описание.

## Зачем удалять мёртвое

Скиллы конкурируют за срабатывание описаниями. Чем их больше, тем хуже точность выбора. Мёртвый скилл — не безобидный балласт: он ухудшает работу живых.

## Границы

Считаются только явные вызовы. Работа, где модель применила правило или сделала задачу без скилла, не учитывается. Логов может не быть вовсе — тогда скилл говорит об этом, а не выдаёт пустоту за «всё мертво».

Других метрик нет: ни экономии токенов, ни качества вывода. Только частота вызовов.

Промпт для модели — [`SKILL.md`](SKILL.md). Домен — [`bear`](../../../../docs/domains/bear/README.md).

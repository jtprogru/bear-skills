# code-last-mile

Достраивает слой опыта использования — те самые «последние 20%», после которых система перестаёт ощущаться сырой.

## Почему этот слой пропускают

Когда задачу декомпозируют, декомпозируют существительное. «Сделать вики» распадается на ingestion, поиск, хранилище, слой LLM. Все части нужны, все делаются — и на выходе получается система, которой невозможно пользоваться.

Опыт использования не появляется в декомпозиции объекта. Не появился — не стал задачей. Не стал задачей — не сделан.

Скилл декомпозирует **сцену** вместо объекта.

## Когда срабатывает

«Вроде работает, но пользоваться невозможно», «чего не хватает до готовности», «доведи до ума», «почему это ощущается сырым».

## Что делает

Находит magic moment — один конкретный момент, ради которого всё делается, с деталями, а не «пользователь работает с системой». Разбирает его по шагам глазами человека: что видит, что делает, чего ждёт и **что видит, когда пошло не так**. Последний вопрос вскрывает больше всего пропусков.

Найденное описывает на уровне сантехники: не «улучшить обработку ошибок», а что именно показать, куда положить, через сколько повторить и что сделать на третьей неудаче.

## Золотые артефакты

Отдельная привычка, которую скилл навязывает: до написания генератора руками написать один-два образцовых результата — идеальную заметку, идеальный ответ.

Пока образца нет, «хорошо» не определено и генератор нечем оценивать. Плюс написание образца само вскрывает недостающие требования: обычно выясняется, что для хорошего результата нужны данные, которые никто не собирался собирать.

## Границы

Один сценарий, разобранный до конца, вместо трёх поверхностных. Не редизайн: достраивает задуманное, а не придумывает другое. Счастливый путь — не результат работы, ошибочные ветки и есть последние 20%.

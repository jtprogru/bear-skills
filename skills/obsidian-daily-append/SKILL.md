# obsidian-daily-append

Добавляет данные в ежедневную заметку текущего дня. Структура заметки нетривиальная — нельзя просто аппендить в конец файла, нужно роутить по разделам и сохранять стиль.

Семантика хранилища, тегов и frontmatter — см. `../../rules/`. Шаблоны — `_Система/1. Шаблоны/`.

---

## Когда НЕ использовать

| Ситуация | Используй вместо |
|----------|------------------|
| Нужна полноценная атомарная заметка с frontmatter | `obsidian-ingest` |
| Ревью недели/месяца, обзор журнала | `obsidian-journal-review` |
| Запись касается прошедшего/будущего дня, не сегодня | вручную |
| Просят разобрать большую заметку или статью | `obsidian-ingest` / `obsidian-split-note` |

---

## Путь к ежедневной заметке

`05. Дневник/YYYY/MM/YYYY-MM-DD.md`, где дата — **сегодняшняя** (см. поле `currentDate` в системном контексте).

Не пиши в заметки прошедших или будущих дней без явного запроса.

---

## Алгоритм

### 1. Определи путь и проверь существование файла

```bash
ls "05. Дневник/<YYYY>/<MM>/<YYYY-MM-DD>.md"
```

**Если файл существует** → переходи к шагу 2.

**Если файла нет** → спроси пользователя:

> Заметки на сегодня (`YYYY-MM-DD.md`) ещё нет. Создать её по шаблону и добавить туда данные?

Жди подтверждения. После «да» — создай заметку с шаблонной шапкой (см. раздел «Создание новой заметки» ниже), затем переходи к шагу 2.

### 2. Определи тип данных

По содержимому пользовательского запроса выбери тип. Если по двум-трём ключевым признакам тип не очевиден — задай **один** уточняющий вопрос с вариантами.

| Тип | Признаки | Целевой раздел |
|-----|----------|----------------|
| **Быстрая мысль / наблюдение** | Короткая идея, личный инсайт без глубокого разбора, эмоция | `### Мысли вслух` |
| **Событие / факт дня** | «Принял таблетку», «встретил X», «получил письмо», «сходил на …» | `### Мысли вслух` (по умолчанию) или отдельный блок, если событие крупное |
| **Встреча / созвон** | Упоминание участника, формата (1:1, синк, созвон, демо) | Sub-блок `### Встреча с [[@nick (Имя)]]` или `### 1:1 с …` |
| **Ссылка на новую атомарную заметку** | Пользователь говорит «оформил мысль», «вынес в заметку», даёт wikilink | `### Заметка дня` |
| **Разбор / узел / инсайт** | «Разобрал узел», «инсайт по X», глубокая саморефлексия | `### Узел №N — <короткая тема>` (N = следующий по счёту) |
| **TODO / решение** | «Не забыть», «надо сделать», «решил, что…», «на завтра» | callout `> [!todo]` под подходящим разделом или в `### Открытые узлы — что дальше` |

**Правило неоднозначности:** если запрос можно разнести по 2+ типам — спроси, не угадывай. Один вопрос лучше неправильной вставки.

### 3. Задай уточняющие вопросы для обогащения

**Минимум один уточняющий вопрос — всегда.** Без исключений «контекст уже полон»: даже если кажется, что всё ясно, у пользователя в голове есть слой, которого нет в исходном запросе. Один вопрос ловит этот слой и экономит вторую правку.

Максимум — два. Если ответ на конкретный вопрос реально очевиден из запроса (пользователь сам дал wikilink на человека / явно указал срок TODO) — этот конкретный вопрос можно пропустить и выбрать другой из таблицы.

**Особенно обязательно** для типов «мысль» и «событие/факт»: они почти всегда тянут за собой неявный контекст (эмоция, причина, связь с другим узлом дня), который пользователь добавит на следующем шаге, если не спросить сразу.

**Универсальные (любой тип):**

- **Связь.** «С каким проектом / MOC / человеком связать?» — ожидай wikilinks. Если связь явно есть в запросе (упомянут человек по нику или проект) — пропусти.
- **Контекст.** «Что предшествовало / при каких обстоятельствах?» — особенно для мысли/инсайта.

**По типу:**

| Тип | Вопросы |
|-----|---------|
| Мысль / инсайт | (1) Стоит ли вынести в атомарную заметку (`obsidian-ingest`)? (2) С какой существующей заметкой связать? |
| Событие / факт | (1) Эмоция / самочувствие? (если личное — таблетка, головная боль, сон). (2) Связать с человеком / проектом? |
| Встреча | (1) С кем именно (wikilink на профиль человека)? (2) Главный итог / что обсуждали в одну строку? |
| Атомарная заметка | (1) Wikilink на созданную заметку. (2) Краткая аннотация — почему она важна сегодня (1–2 предложения). |
| Разбор / узел | (1) Главный сдвиг рамки в одну фразу. (2) Связанные заметки / люди / MOC. (3) TODO на завтра/неделю? |
| TODO | (1) Срок (на завтра / на этой неделе / без срока). (2) К какому проекту / узлу относится? |

**Стиль вопроса:** короткие, конкретные, по одному пункту за раз. Не пиши «расскажи поподробнее» — это не вопрос.

### 4. Сформируй фрагмент

Стиль и форматирование — по `../../rules/content-style.md`:

- Русский язык, технические термины на английском
- Личный тон, не канцелярит, не «вы»
- Wikilinks на упомянутых людей, проекты, MOC, заметки
- Callout-блоки `> [!todo]`, `> [!info]`, `> [!warning]` где уместно
- Имена людей — с никнеймом и реальным именем: `[[@nick (Имя Фамилия)]]`

**Шаблоны фрагментов:**

**Мысль / событие:**
```
<1–3 предложения от первого лица или безлично, с wikilinks где уместно>
```

**Встреча:**
```
#### Встреча с [[@nick (Имя)]]

<1–3 предложения: контекст, итог, связанные темы через wikilinks>
```

**Ссылка на атомарную:**
```
Оформил мысль: [[Название атомарной заметки]] — <краткая аннотация, почему важна сегодня>.
```

**Узел разбора:**
```
#### Узел №N — <короткая тема>

Заметка: [[Название атомарной заметки]] (если есть)

<2–4 предложения: главный сдвиг рамки, ключевая находка, связь с другими узлами>
```

**TODO:**
```
> [!todo] **<срок>** — <конкретное действие>. <Контекст: почему / зачем / связь>.
```

### 5. Вставь в нужный раздел

**Если раздел уже есть** в заметке — добавь фрагмент в его конец, отделив пустой строкой. Не дублируй существующие записи.

**Если раздела нет** — создай его. Порядок разделов в заметке (если все есть):

1. `## Дневник` (всегда есть после шапки)
2. `### Узел №1`, `### Узел №2`, …
3. `### Конкретные находки сессии` / `### Список искр` (если был разбор)
4. `### Открытые узлы — что дальше` (TODO)
5. `### Что важно зафиксировать на завтра`
6. `### Мысли вслух`
7. `### Заметка дня — <тема>`

При добавлении нового раздела вставь его в правильное место по этому порядку, а не в конец файла.

**Используй `Edit` (не `Write`)** — никогда не перезаписывай файл целиком.

### 6. Покажи план до вставки — всегда

**Перед каждым `Edit` выводи короткий план и жди подтверждения.** Не оценивай «тривиальность» сам — даже однострочный факт может попасть не в тот раздел или не в той формулировке. Цена показать preview — одна реплика; цена молча записать неверно — повторная правка.

```
План:
- Файл: 05. Дневник/2026/05/2026-05-08.md (существует / создать)
- Тип: <тип>
- Раздел: ### <раздел> (существует / создать)
- Фрагмент:
  <preview фрагмента>
```

**Единственное исключение:** пользователь в текущем запросе явно сказал «без подтверждения», «делай сразу», «не спрашивай». Тогда сразу к шагу 7. На прошлые сессии это правило не распространяется — каждый запрос оценивается отдельно.

### 7. Отчитайся

Краткая сводка: что добавлено, в какой раздел, какие связи поставлены. Если в ходе уточнений выяснилось, что мысль глубокая и стоит вынести в атомарную заметку — предложи запустить `obsidian-ingest` отдельно.

## Создание новой заметки

Если файл `05. Дневник/YYYY/MM/YYYY-MM-DD.md` отсутствует — после подтверждения создай его с шапкой:

```markdown
---
tags:
  - journal/daily
aliases: []
---

**< [[<вчера-YYYY-MM-DD>|Вчера]] | [[<YYYY-Www>|Неделя]] | [[<YYYY-MMM>|Месяц]] | [[<завтра-YYYY-MM-DD>|Завтра]] >**

## Дневник

> [!info] Записывай не только рабочие мысли, но и свои собственные

```

**Расчёт wikilinks навигации:**

- Вчера: `<сегодня - 1 день>` в формате `YYYY-MM-DD`
- Неделя: `YYYY-Www` где `ww` — ISO-номер недели сегодняшней даты с ведущим нулём (например, `2026-W19`)
- Месяц: `YYYY-MMM` где `MMM` — `M` + двузначный номер месяца (например, `2026-M05`)
- Завтра: `<сегодня + 1 день>` в формате `YYYY-MM-DD`

Можно посчитать через `date` в shell:

```bash
date -v-1d +%Y-%m-%d  # вчера (BSD/macOS)
date -v+1d +%Y-%m-%d  # завтра
date +%Y-W%V          # ISO-неделя (формат W##)
date +%Y-M%m          # месяц
```

Если родительских папок (`YYYY/`, `MM/`) нет — создай через `mkdir -p`.

После создания — продолжи с шага 2 алгоритма.

## Примеры

### Пример 1 — событие/факт

Запрос: «добавь в сегодняшнюю заметку, что выпил спазган от головы»

Уточнение: «Связать с конкретной заметкой о здоровье / препарате? И эмоция/контекст — устал, перенапрягся?»

Ответ пользователя: «связать со Спазган, контекст — после сессии саморазбора»

План:
- Файл: `05. Дневник/2026/05/2026-05-08.md` (существует)
- Тип: событие/факт
- Раздел: `### Мысли вслух` (существует)
- Фрагмент:
  ```
  После долгой сессии саморазбора возникла головная боль, принял таблетку [[Спазган]].
  ```

### Пример 2 — ссылка на атомарную

Запрос: «запиши в дневник, что я оформил мысль про признание себя — [[Признание себя как форма силы]]»

Уточнение: «Краткая аннотация — почему важна сегодня?»

Ответ: «смещает фокус с внешнего признания на внутреннее»

План:
- Раздел: `### Заметка дня — про признание себя` (создать, если нет аналогичного)
- Фрагмент:
  ```
  Оформил мысль: [[Признание себя как форма силы]] — смещает фокус с внешнего признания на внутреннее.
  ```

### Пример 3 — TODO

Запрос: «добавь TODO в today: на этой неделе написать Синицыну»

Уточнение: «К какому проекту / узлу привязать? Это про peer-контур из сегодняшнего разбора?»

Ответ: «да, peer-эксперимент»

План:
- Раздел: `### Открытые узлы — что дальше` (создать или дополнить)
- Фрагмент:
  ```
  > [!todo] **На этой неделе** — написать [[@boombick (Синицын Андрей)|Синицыну]]. Цель: запустить continuity-эксперимент в peer-круге.
  ```
